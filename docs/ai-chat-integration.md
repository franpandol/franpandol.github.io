# AI chat integration ("Ask about Francisco")

A small chat widget on the site answers questions about Francisco's experience, skills and
availability. Answers come from an LLM, but only from excerpts of his own CV. Anything the
CV doesn't cover is refused without calling the chat model.

Everything runs on Cloudflare: Pages (static site + Functions), Workers AI (models),
Turnstile (bot protection) and, optionally, AI Gateway (logging).

## Files

| File | Role |
|---|---|
| `src/components/ChatWidget.jsx` | Floating chat UI, Turnstile widget, SSE streaming client |
| `src/constants/turnstile.js` | Turnstile site key and action name (`chat`) |
| `functions/api/chat.js` | `POST /api/chat`: the whole backend pipeline |
| `functions/lib/cvRetrieve.js` | Chunking, embeddings, similarity ranking of the CV |
| `functions/lib/chatScope.js` | Refusal text and a helper that fakes an SSE stream |
| `functions/lib/aiGateway.js` | Builds the optional AI Gateway options for every `env.AI.run` call |
| `functions/_middleware.js` | Unrelated to chat; serves `/site.md` to AI crawlers |
| `public/site.md` | The CV as markdown. This is the knowledge base. Generated by `npm run generate:md` |
| `wrangler.jsonc` | Declares the `AI` binding and `TURNSTILE_HOSTNAMES` |

## Request flow

```
Browser (ChatWidget)
  1. User opens widget -> Turnstile challenge renders, yields a single-use token
  2. User sends message -> POST /api/chat { messages, lang, cf-turnstile-response }
        |
        v
functions/api/chat.js
  3. Parse JSON body                              (400 on bad JSON)
  4. Verify Turnstile token with Cloudflare       (403 + code on failure)
  5. Validate messages                            (400 on bad shape)
  6. Load /site.md via env.ASSETS
  7. Retrieve relevant CV chunks (embeddings)     (502 if retrieval throws)
  8. No chunk scores high enough?  -> stream a canned refusal, stop (no chat model call)
  9. Build system prompt with the top chunks
 10. env.AI.run(chat model, stream: true)         (optionally via AI Gateway)
 11. Return the model's SSE stream as-is
        |
        v
Browser
 12. Parse SSE chunks, append tokens to the assistant bubble
 13. When the stream ends, append the contact CTA line (deterministic, not model-generated)
```

### 1. Bot protection (Turnstile)

- The widget renders a Turnstile challenge when opened. The token is **single-use**: the
  client clears it right after sending and resets the widget in `finally`. The Send button
  stays disabled until a fresh token exists.
- The server verifies every request with Cloudflare's `siteverify` endpoint. It fails
  closed on anything unexpected: missing token, missing secret, network error, bad JSON,
  `success !== true`, wrong `action` (must be `chat`), or a hostname not in
  `TURNSTILE_HOSTNAMES` (default `franpandol.com`). It has a 10 s timeout.
- On failure the server returns 403 with a `code` (for example `missing_token`,
  `hostname_mismatch`). The client shows the Turnstile error message on any 403.

### 2. Input validation

`isValidMessages` requires: an array of 1 to 12 messages, each with role `user` or
`assistant`, non-empty string content, at most 500 characters. The client also trims the
history to the last 12 messages.

### 3. Retrieval (`cvRetrieve.js`)

This is the guard that keeps the bot on topic. Instead of maintaining a list of banned or
off-topic phrases, the bot only answers when the question matches CV content.

1. **Chunking**: `public/site.md` is split at markdown headings (`#` to `###`). Chunks under
   40 characters are dropped. Sections over 1200 characters are split into paragraph groups.
2. **Embedding**: chunks are embedded with `@cf/baai/bge-m3` (Workers AI). The chunk index
   is cached in module memory, keyed by a hash of the markdown. It is rebuilt on a cold
   isolate or when the CV changes.
3. **Scoring**: the user's latest question is embedded and compared with every chunk.
   `score = 0.75 * cosine similarity + 0.25 * lexical overlap`. The lexical part is the
   fraction of question words (3+ letters, accent-stripped) that appear in the chunk. It
   helps exact matches like skill or company names.
4. **Threshold**: if the best score is below `MIN_SCORE = 0.32`, retrieval returns no
   chunks. Otherwise the top `TOP_K = 4` chunks are returned.

### 4. Refusal path

If retrieval returns no chunks, `chat.js` returns a canned message (EN or ES) as a fake SSE
stream (`sseTextStream`). It uses the same chunk shape the widget already parses. The chat
model is never called, so off-topic questions cost only the embedding call.

### 5. Generation

The chat model is `@cf/ibm-granite/granite-4.0-h-micro` via the `AI` binding. The system
prompt (`buildSystemPrompt`) tells it to:

- answer only from the CV excerpts, which are pasted in between markers;
- say it can only answer from the CV if the excerpts don't contain the answer;
- never write code or give programming help;
- keep answers to 2 to 4 sentences;
- reply in the request language (`lang` is `es` or defaults to `en`);
- not add a closing "contact Francisco" line, because the client adds it.

The user/assistant history is sent after the system message, with `stream: true`. The
response stream is passed straight back to the browser (`text/event-stream`).

Defense in depth against off-topic use has three layers: the retrieval threshold, the
system prompt, and the fact that the model only sees CV excerpts.

### 6. Client streaming

`streamChatResponse` reads the response body, splits it on blank lines, and handles
`data:` lines. It ignores `[DONE]` and malformed chunks. The token is read from
`choices[0].delta.content`, with `parsed.response` as a fallback for the older flat format.

While the assistant message is empty and streaming, the bubble shows "…". After the stream
ends, the client appends `chat.ctaLine` (with the email) itself, so the nudge always shows.
On any error the empty assistant bubble is removed and an error line is shown.

## Configuration

| Name | Where | Purpose |
|---|---|---|
| `AI` | `wrangler.jsonc` binding | Workers AI access (embeddings + chat model) |
| `TURNSTILE_SECRET` | Pages secret | Server-side Turnstile verification. Required |
| `TURNSTILE_HOSTNAMES` | `wrangler.jsonc` var | Comma-separated allowed hostnames (default `franpandol.com`) |
| `AI_GATEWAY_ID` | Pages variable | Optional. Enables AI Gateway logging. Use `default` |
| Turnstile site key | `src/constants/turnstile.js` | Public key used by the widget |

For local dev, `wrangler pages dev` reads secrets and variables from `.dev.vars`. The `AI`
binding still calls the real Workers AI and needs a Cloudflare login.

## Seeing requests and responses (AI Gateway)

If `AI_GATEWAY_ID` is set, every Workers AI call, the chat call and both embedding calls,
gets a third argument from `gatewayOptions(env)` in `functions/lib/aiGateway.js`:

```js
env.AI.run(MODEL, payload, { gateway: { id: gatewayId, collectLog: true } })
```

Cloudflare then logs each request (prompt including the CV excerpts, response, tokens,
latency, errors) in the dashboard under AI -> AI Gateway -> Logs. If the variable is unset,
`gatewayOptions` returns `undefined`, the call is unchanged and nothing is logged.

Notes:

- A single chat message can produce up to three log entries: the CV chunk embeddings (only
  on a cold isolate), the question embedding, and the chat completion.
- The stored prompts contain visitor messages and CV text. Check log retention settings.
- A default gateway (id `default`) is created automatically on the first authenticated
  request, according to the dashboard. Whether that also happens for requests made through
  the binding is unverified. If logs don't appear, create the gateway by hand.
- Cost and limits: AI Gateway's core features are free. Gateways created on or after
  2026-09-24 use Workers Logs pricing (Free plan: 200,000 log events/day, 3-day retention).
  Model usage is billed as normal Workers AI usage.

Without the gateway, `wrangler pages deployment tail <deployment-id-or-url> --project-name
franpandol-github-io` streams function logs, but the code doesn't log anything by default.

## Latency notes

Each message makes up to three model calls: embed the question, embed the CV chunks (only on
a cold isolate), then the chat model. The first request after a deploy or idle period is
the slowest, because the whole CV must be embedded and the chat model may be cold. There is
no timeout on the `env.AI.run` calls, so a slow model shows the "…" bubble for as long as it
takes. Off-topic questions skip the chat model and return faster.

## Changing things

- **Update the CV**: edit `experience.json` / `experience.es.json`, then run
  `npm run generate:md`. The retrieval index rebuilds itself when `site.md` changes.
- **Tighter or looser scope**: adjust `MIN_SCORE` in `cvRetrieve.js`. Higher refuses more.
  Lower lets vaguer questions through to the model.
- **Change the model**: edit `MODEL` in `chat.js`. If the new model streams a different SSE
  shape, update the parsing in `ChatWidget.jsx`.
- **Answer length or tone**: edit `buildSystemPrompt` in `chat.js`.
- **Refusal wording**: edit `outOfScopeRefusal` in `chatScope.js`.

## Tests

Run everything with `npm test`. Function tests live next to the code:

- `functions/api/chat.test.js`: the endpoint end to end with mocked `env.AI`, `env.ASSETS` and
  Turnstile `siteverify`. It covers JSON and message validation, every Turnstile failure code,
  the 502 on retrieval failure, the off-topic refusal (EN/ES, chat model not called), the
  grounded system prompt, language handling, SSE headers, and gateway routing on or off.
- `functions/lib/cvRetrieve.test.js`: chunking, similarity, lexical overlap, and gateway
  options on embedding calls.
- `functions/lib/aiGateway.test.js`: the gateway option helper.
- `src/components/ChatWidget.test.jsx`: the widget.

The tests mock the models, so they check the pipeline's behaviour, not answer quality. The
similarity threshold (`MIN_SCORE`) is not tested against the real embedding model.
